> **01**
> **真实开发痛点**

在使用 AI 编程助手进行日常开发时，几乎所有人都会遇到一系列共性问题：
-   每次新建会话，都必须重新向 AI 描述项目架构、技术栈、目录规范、历史踩坑点，大量时间消耗在重复沟通上
-   内置的简易记忆机制（如 \`CLAUDE.md\`、\`.cursorrules\`）普遍只有 200 行左右容量，内容极易溢出、过期、混乱
-   多工具协同场景下（Cursor + Claude Code + Gemini CLI 等），记忆无法互通，每个工具都需要重新 “教学”
-   为了保证 AI 理解上下文，不得不反复粘贴大量代码片段与历史信息，导致 Token 消耗急剧上升，成本难以控制
-   传统记忆方案要么依赖复杂向量数据库，要么需要手动调用 API 记录，配置门槛高、稳定性差
-   无法直观查看 AI 到底记住了什么、记忆是否准确、会话历史如何沉淀，缺乏可视化观测手段
这些问题直接降低开发效率、提升使用成本，也让 AI 助手难以真正成为长期稳定的协作伙伴。
> **02**
> **项目简介与定位**

**agentmemory** 是 GitHub 上持续热门的开源项目，基于 **iii engine** 构建，专注为 AI 编程 Agent 提供轻量化、高性能、跨平台的**持久化记忆系统**。
![[笔记同步助手/images/47a5e17ce391f1afde19548afda44712_MD5.png]]
它可以理解为 AI 编程助手的**外置长期记忆大脑**：
一次配置，全程自动运行，静默记录开发者的操作习惯、项目结构、代码逻辑、问题解决方案，并在新会话中自动召回关键上下文，让 AI 始终保持对项目的连贯认知。
![[笔记同步助手/images/542f64dc2279ce3d943767f655c734bb_MD5.png]]
项目完全开源，遵循 Apache-2.0 协议，无需外部数据库依赖，支持 Windows /macOS/ Linux 全平台，兼容超过 32 种主流 AI 编程客户端，包括 Claude Code、Cursor、Gemini CLI、Codex、Hermes、OpenClaw、Cline、Goose 等。
![[笔记同步助手/images/8198e54a2b13d0340e3e4776e2d4535c_MD5.gif]]
其设计思路在 Karpathy LLM Wiki 模式基础上扩展，增加置信度评分、记忆生命周期管理、知识图谱与混合检索能力，实现更接近人类的知识沉淀与调用方式。
> **03**
> **核心解决问题**

agentmemory 从根源上解决 AI 编程助手的几大核心痛点：
1.  **会话失忆问题**  
    关闭会话、重启工具后，AI 不再 “清零记忆”，历史架构、代码逻辑、Bug 解决方案自动保留。
2.  **重复上下文投喂**  
    无需每次手动粘贴
    项目信息，系统自动检索并注入关键记忆，大幅减少重复操作。
3.  **跨工具记忆孤岛**  
    单一记忆服务，可被多个 AI Agent 同时接入，实现记忆互通、统一管理。
4.  **Token 成本爆炸**  
    通过精准检索替代全文注入，Token 用量降低 92%，长期使用成本显著下降。
5.  **配置复杂、依赖繁重**  
    内置 SQLite，无需部署 PostgreSQL、Qdrant、Redis 等中间件，一条命令启动。
6.  **记忆不可观测、不可管理**  
    提供内置 Web 查看器，支持会话回放、知识图谱展示、记忆编辑与审计。
7.  **敏感信息泄露风险**
内置隐私过滤机制，自动剔除 API Key、Token、密钥等敏感内容，仅保留业务逻辑记忆。
> **04**
> **核心技术能力**

**（1）全自动记忆捕获**
通过 12 个内置生命周期钩子实现无感采集：
-   会话启动 / 结束
-   用户提问提交
-   工具调用前后
-   执行失败异常
-   子 Agent 生命周期
全程无需手动调用 \`remember\` 或 \`add\`，完全自动化运行。
**（2）四层记忆架构（类人脑记忆机制）**
-   **工作记忆**：短期原始观测记录，对应短时记忆
-   **情景记忆**：会话级压缩摘要，记录 “发生了什么”
-   **语义记忆**：结构化事实与知识点，沉淀 “知道什么”
-   **过程记忆**：工作流与模式固化，掌握 “应该怎么做”
记忆会随时间自动衰减、强化、合并、更新，避免冗余与冲突。
**（3）三重混合检索**
采用 BM25 关键词检索 + 向量语义检索 + 知识图谱关联检索，通过 RRF 重排序融合结果，实现极高精准度。
**（4）全平台 MCP 兼容**
![[笔记同步助手/images/66d33827d44a51f8f69199f1b13f3ae7_MD5.png]]
提供标准 MCP（Model Context Protocol）服务，支持所有兼容 MCP 的 AI 客户端接入，统一暴露 53 个工具接口，包括：
-   智能搜索
-   记忆保存 / 删除
-   会话历史
-   项目档案
-   知识图谱查询
-   审计与快照
-   团队共享
**（5）实时可视化查看器**
内置 Web UI 运行在 3113 端口，支持：
![[笔记同步助手/images/663b3aa22e0daf9310a6bf1e5d1930cb_MD5.png]]
-   实时记忆流查看
-   会话时间线回放
-   速度控制（0.5×–4×）
-   知识图谱可视化
-   健康状态监控
**（6）零外部依赖**
内置存储引擎，不依赖任何第三方数据库，开箱即用，同时支持本地离线向量模型，完全内网可用。

> **07**
> **极速上手全流程**

**环境要求**
-   Node.js ≥ 20
-   （可选）Docker（Windows 推荐）
**方式 1：全局安装（推荐）**
```
# 安装到全局npm install -g @agentmemory/agentmemory
```
macOS / Linux 若出现权限错误：
```
sudo npm install -g @agentmemory/agentmemory
```
**方式 2：免安装直接运行**
```
npx @agentmemory/agentmemory
```
强制使用最新版本：
```
npx -y @agentmemory/agentmemory@latest
```
**启动记忆服务**
```
agentmemory
```
服务默认启动在：
-   REST API：\`http://localhost:3111\`
-   实时查看器：\`http://localhost:3113\`
**该终端窗口需保持打开**。
**运行演示示例**
新开终端执行：
```
agentmemory demo
```
该命令会自动导入 3 组真实开发场景（JWT 认证、N+1 查询优化、限流逻辑），并执行语义搜索测试，验证混合检索能力。
**基础常用命令**
```
agentmemory stop        # 停止服务
agentmemory remove      # 清理所有本地数据
agentmemory doctor      # 自动诊断并修复环境问题
agentmemory upgrade     # 升级到最新版本
```
> **08**
> **主流编程 Agent 配置**

**（1）Cursor 配置**
1.  打开 Cursor 设置，找到 MCP 配置文件 \`～/.cursor/mcp.json\`
2.  在 \`mcpServers\` 节点中添加：
```
"agentmemory": {
"command": "npx",
"args": ["-y", "@agentmemory/mcp"],
"env": {
"AGENTMEMORY_URL": "http://localhost:3111"
}
}
```
1.  重启 Cursor 即可生效。
**（2）Claude Code 配置**
```
agentmemory connect claude-code --with-hooks
```
自动完成插件注册、钩子配置、MCP 服务对接。
**（3）Gemini CLI 配置**
```
gemini mcp add agentmemory npx -y @agentmemory/mcp --scope user
```
**（4）Codex CLI 配置**
```
codex plugin marketplace add rohitg00/agentmemory
codex plugin add agentmemory@agentmemory
```
**（5）通用 MCP 配置格式**
所有支持 MCP 协议的客户端均可使用以下标准配置：
```
"agentmemory": {
"command": "npx,
"args": ["-y", "@agentmemory/mcp"],
"env": {
"AGENTMEMORY_URL": "http://localhost:3111"
}
}
```

> **10**
> **常见问题与排查**

**（1）端口 3111 被占用**
-   Windows：\`netstat -ano | findstr :3111\`
-   macOS/Linux：\`lsof -i :3111\`
结束对应进程后重新启动。
**（2）无法打开查看器 http://localhost:3113**
-   确认 \`agentmemory\` 服务正在运行
-   检查防火墙是否放行端口
-   确认无代理工具拦截本地请求
**（3）Demo 运行无结果**
-   重新执行 \`agentmemory demo\`
-   确认 Node 版本 ≥ 20
-   关闭代理后重试
**（4）MCP 工具只显示 7 个基础能力**
-   确认 \`agentmemory\` 服务正常启动
-   检查 \`AGENTMEMORY\_URL\` 配置正确
-   重启 AI 客户端重新加载 MCP
**（5）Windows 环境启动异常**
优先使用 Docker Desktop 模式，系统会自动调用容器运行，避免原生环境兼容问题。
> **11**
> **最佳实践建议**

1.  **首次使用完整描述项目**  
    在第一个会话中清晰说明项目架构、技术栈、目录规范、禁忌与历史问题，便于系统构建高质量基础记忆。
2.  **优先使用本地嵌入模型**  
    无需 API Key、不依赖外网、速度更快、完全免费，适合内网与隐私敏感场景。
3.  **多工具共用同一服务**  
    只需启动一个 agentmemory 实例，所有 AI 客户端接入同一地址，实现全局记忆同步。
4.  **定期查看记忆面板**  
    通过查看器检查记忆准确性，删除错误记忆，避免误导后续开发。
5.  **重要项目开启记忆快照**  
    使用快照功能备份关键记忆节点，支持版本回滚与对比。
6.  **团队场景开启知识图谱与共享模式**  
    实现成员间记忆互通，提升团队协作一致性。
7.  **避免手动修改底层存储文件**
所有记忆操作优先通过面板或 MCP 工具完成，保证数据结构完整性。
